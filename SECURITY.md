# Security policy

## Supported versions

Security fixes are released for the latest published version.

| Version        | Supported |
| -------------- | --------- |
| Latest release | Yes       |
| Older releases | No        |

Upgrade to the latest release before reporting a vulnerability that may already be fixed.

## Reporting a vulnerability

Do not report suspected vulnerabilities in a public issue, discussion, or pull request.

Email [developermadan+jose@gmail.com](mailto:developermadan+jose@gmail.com) with the subject
`[SECURITY] @josesuite/node`. Include:

- the affected package version and Node.js version;
- a description of the vulnerability and its security impact;
- the conditions needed to reproduce or exploit it;
- the smallest reproducible example or proof of concept available; and
- any suggested mitigation or fix, if you have one.

Use test keys and test data. Do not send real tokens, credentials, private keys, secret key
material, or confidential plaintext.

## What to expect

The maintainers will confirm receipt, assess the report, and keep you informed as the investigation
progresses. They may ask for more information or help reproducing the issue. Confirmed
vulnerabilities will be addressed according to their severity and the work needed to release a
safe fix.

Please keep the report private until the maintainers have released a fix or agreed to a disclosure
date. The maintainers will coordinate public disclosure and credit with the reporter. You may
remain anonymous or decline credit.
